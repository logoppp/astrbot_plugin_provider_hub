# 供应商配置中心 · AstrBot 插件

一个给 [AstrBot](https://github.com/AstrBotDevs/AstrBot) 用的配置聚合面板。
把所有插件里「用哪个模型」的选项扫到同一页，一处改完、批量保存。

> 版本 1.1.0 · 作者 logoppp · MIT License

---

## 它解决什么问题

AstrBot 的模型供应商集中在 `cmd_config.json` 里，但**每个插件各存一份「用哪家」的引用**。
插件一多，就会出现这种局面：

- 想换个对话模型，得挨个打开每个插件、找到那一项、改完保存、等它重载；
- 某个插件很久没打开过，它还在用已经删掉的供应商，而且没有任何提示；
- 到底哪几个插件配了向量模型、哪几个还是空的，没人说得清。

这个插件把这一层抽出来：**所有 `select_provider` 系列的字段，集中到一页里看和改。**

---

## 功能

- **自动发现**：扫描 `data/plugins/*/_conf_schema.json`，找出所有 `_special` 为
  `select_provider` / `select_provider_embedding` / `select_provider_rerank` /
  `select_provider_tts` / `select_provider_stt` 的字段。
- **按类别筛选**：对话 / 向量 / 重排 / 语音合成 / 语音识别，只列出实际存在的类别，带数量。
- **搜索与「只看未配置」**：按插件名、字段名、配置路径、当前值搜索；一键列出所有还空着的项。
- **批量保存**：改动先在页面里攒着，一次提交；后端按插件合并，**每个插件只写一次文件、只重载一次**。
- **自动备份**：写盘前复制一份 `<配置文件>.bak_hub_<时间戳>`，同一秒内多次保存也不会互相覆盖。
- **自动重载**：保存后调用插件管理器重载对应插件，配置立刻生效；重载失败会明确提示「待重载」。
- **只改白名单字段**：写入前重新解析 schema 校验路径，只允许改官方供应商引用项，其余一律拒绝。

## 工作原理

```
cmd_config.json ──┐
                  ├─→ 页面（按 kind 过滤候选供应商）
plugins/*/_conf_schema.json ─→ 发现字段
                  │
plugins/*_config.json ←────── 保存（先备份，再写，再重载）
```

| 读什么 | 写什么 |
|---|---|
| `data/cmd_config.json` 的 `provider` 数组（只取 id / model / kind / enable） | `data/config/<插件名>_config.json` 里对应的字段路径 |
| `data/plugins/<插件>/\_conf_schema.json` | 只写 schema 里声明过 `_special` 的路径 |

字段路径支持嵌套（`items.xxx`），用点号分隔，例如 `optimizer.llm_provider_id`。

## 安装

1. 把整个目录放进 AstrBot 的 `data/plugins/` 下，目录名保持 `astrbot_plugin_provider_hub`。
2. 重启 AstrBot，在插件管理里启用「供应商配置中心」。
3. 打开本插件详情页的「provider-hub」页面。

无第三方依赖（只用标准库和 AstrBot 自带的 Web 框架）。

## 使用

页面分三块：

| 区域 | 作用 |
|---|---|
| 顶部 | 插件数 / 配置项数 / 未配置数，以及「刷新」「放弃改动」「保存全部改动」 |
| 筛选行 | 关键词搜索、类别筛选（彩色玻璃胶囊）、「只看未配置」 |
| 列表 | 按插件分组；每行是「字段 → 供应商下拉 → 状态 + 保存」 |

每行可以单独保存，也可以改完多处后点右上角**保存全部改动**（`Ctrl`/`Cmd` + `S` 同效）。
有未保存改动时，行会亮起左侧强调条，顶栏出现「N 项待保存」的角标。

状态含义：

| 状态 | 含义 |
|---|---|
| 未配置 | 这个字段还没选供应商 |
| 已配置 | 已选，且与配置文件一致 |
| 未保存 | 改了但还没写盘 |
| 已生效 | 已写盘，且插件重载成功 |
| 待重载 | 已写盘，但插件重载失败，需要手动重载 |
| 失败 | 写入或校验失败，鼠标悬停提示里有原因 |

## 安全与边界

- **只改白名单字段**：写入前会重新解析该插件的 schema，路径不在 `select_provider` 系列里就直接拒绝，
  避免构造请求改到任意配置。
- **先备份再写**：备份文件名带时间戳，同秒冲突时追加序号，不会被覆盖。
- **不做全局替换**：只碰你提交的那几个键，其它字段原样保留（按原有缩进重写 JSON）。
- **面板权限**：页面走 AstrBot 自带的面板登录态，能打开面板的人本来就能改配置，不额外引入账号体系。

## 局限

- 只能改声明了 `_special: select_provider*` 的字段。普通文本框、开关不在范围内——这是刻意的，
  范围越大越容易误改。
- 依赖插件的配置文件是 `data/config/<插件名>_config.json` 这种默认命名。
- 重载依赖 AstrBot 的插件管理器；管理器接口变化时可能退化成「待重载」，此时手动重载即可。

## 目录结构

```
astrbot_plugin_provider_hub/
├── main.py                       # 扫描 schema、读写配置、批量保存、重载
├── metadata.yaml
├── views/provider-hub/index.html # 单页界面（无构建步骤）
└── LICENSE
```

界面是单个 HTML 文件，不依赖任何前端框架或打包工具，改完刷新即可看到。
